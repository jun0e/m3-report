Why is the OLS β negative for most combos? The cells-cleared regression includes BOTH individual PU counts AND combo counts as predictors. The pu_stats aggregate appears to count combo participants in the individual counts (so a rocket+bomb combo adds 1 to pu_stats.rocket and 1 to pu_stats.bomb). The combo β then represents the additional cells beyond what the constituent solo activations contribute. A near-zero or negative combo β means: combos clear roughly the same number of cells as the same pieces would individually — they're a visual UX moment, not a damage multiplier. Rainbow+rainbow's exceptionally negative β (~-20) reflects that it wipes one color from the board in a single event but then the attempt has no remaining play — net cells cleared is lower than attempts without the wipe. Extended-model R² = 0.7847 (vs basic-model R² = 0.7822) — adding combo predictors barely improves fit, which itself supports the "combos = solo equivalent" interpretation.

Activation timing — moveNum distribution per PU type

When in a level does each PU type fire? Binned by 5-move windows. Stacked area chart — early bins = quick-trigger, late bins = save-for-later behavior.
Methodology: Window = 120 hours UTC. Production-only filter applied (build_name starting with "Live-"). Damage inference uses OLS regression on 87,402 level attempts: cellsCleared = β_rocket·#rockets + β_plane·#planes + β_bomb·#bombs + β_rainbow·#rainbows + intercept. The intercept (53.8 cells) represents an attempt's baseline clearance from regular match-3 with zero PUs. R² = 0.782 — PU counts explain that share of variance in cells cleared. Simple-ratio damage = avg cells in attempts WITH a PU type minus avg WITHOUT — it over-attributes credit because users who use one type often use others; the OLS β is the credibly causal estimate. Per-activation damage is not directly logged (no cellsCleared field on pu_activated); all damage figures are inferred from per-attempt aggregates.
